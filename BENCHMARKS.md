# Benchmarks

Reproducible numbers comparing DMKDE against four classical anomaly
detection methods on two real datasets and three synthetic scenarios.

All results were generated by the scripts in `python/` against
`libdmkde 0.1.0`, `scikit-learn 1.8.0`, `numpy 2.4.6`, and Python 3.12 on
Linux x86_64. `score_samples` in 0.1.1 is bit-identical to 0.1.0. 0.2.0
draws the random features with a portable sampler (same model on every OS),
which on Linux agrees with 0.1.x's weights to ~1e-10 relative; re-running
with 0.2.0 on Linux x86_64 reproduced every AUC below to the printed digits
(synthetic seed 42 and seeds 0-9, KDDCup seed 42, credit card; the KDDCup
seed 1 / 2 rows were not re-run). On macOS and Windows 0.1.x drew different
weights, so these exact numbers are Linux numbers for 0.1.x and portable
from 0.2.0 on.

**Timings were measured with 0.1.0** on one laptop core and were not
re-measured for 0.1.1 or 0.2.0 (the machine is shared, so new timings would
not be comparable). Treat every `fit` / `inference` column as a 0.1.0
measurement; 0.1.1 and later `fit` is slower (see below).

**Read these numbers with three caveats:**

- **One split, one seed.** Every table below is a single-split evaluation:
  one train/test split with seed 42. Several gaps between detectors are
  smaller than the seed-to-seed variation; the "Seed variation" sections
  show where the winner changes with the seed.
- **σ was not chosen by a held-out protocol.** DMKDE's `sigma` and
  `feature_dim` were picked by hand on the same seed-42 split that is
  reported, while the baselines ran at library defaults. The DMKDE numbers
  are therefore optimistic relative to the baselines. DMKDE is sensitive to
  σ (see "Unique capabilities" below).
- **No confidence intervals.** A multi-seed, held-out benchmark program is
  planned for 0.2.0.

## Detectors compared

| Detector | Source |
|---|---|
| **DMKDE** | This library — Born-rule density-matrix scoring with RFF embedding |
| Mahalanobis | This library — negative Mahalanobis distance |
| Isolation Forest | scikit-learn — Liu et al. 2008 |
| One-Class SVM | scikit-learn — Schölkopf et al. 2001 |
| Local Outlier Factor | scikit-learn — Breunig et al. 2000 |

## Real datasets

### Kaggle Credit Card Fraud (`benchmark_creditcard.py`)

- 284,807 transactions, 492 fraudulent (0.173% positive rate)
- 30 features: Time + 28 PCA-transformed (V1–V28) + Amount
- Fetched via `sklearn.datasets.fetch_openml('CreditCardFraudDetection', version=1)`
- Split: 10,000 random normals → train; 10,000 held-out normals + all 492 fraud → test
- StandardScaler applied to training set only

Times were measured with 0.1.0; 0.1.1 `fit` is 2-6× slower (leave-one-out
threshold and validation). AUCs are unchanged.

DMKDE hyperparameters: `feature_dim=1024`, `sigma=7.0` (not the script
defaults; pass `--feature_dim 1024 --sigma 7.0`)

| Detector | ROC-AUC | PR-AUC | fit (0.1.0) | inference (0.1.0) |
|---|---:|---:|---:|---:|
| **Mahalanobis** | **0.9616** | **0.8720** | 0.01s | 0.01s |
| LOF | 0.9512 | 0.8443 | 0.43s | 0.39s |
| OneClassSVM | 0.9509 | 0.8217 | 0.60s | 0.42s |
| Isolation Forest | 0.9490 | 0.6599 | 0.31s | 0.13s |
| DMKDE | 0.9546 | 0.7391 | 21.4s | — |

**Honest result:** Mahalanobis wins by ~1% ROC-AUC. This is the
expected behaviour — the V1–V28 features are PCA-orthogonalised, so the
"normal" distribution post-PCA is essentially a single Gaussian, which
is exactly Mahalanobis's optimal regime. By ROC-AUC DMKDE is second
(0.9546), above LOF (0.9512) and OneClassSVM (0.9509), but those
differences are within the noise of one split. **By PR-AUC, the more
relevant metric at a 0.17% positive rate, DMKDE ranks 4th of 5: 0.74,
0.10 behind LOF (0.84) and 0.08 behind OneClassSVM (0.82), ahead only
of Isolation Forest (0.66).**

### KDDCup'99 SA subset (`benchmark_kdd.py`)

- 100,655 network flows (SMTP+HTTP, 10% sample), 3,377 intrusions (3.36%)
- 38 numeric features: the 3 categorical columns (`protocol_type`,
  `service`, `flag`) are **dropped**, so this is a numeric-features-only
  result, not evidence about mixed feature types
- Fetched via `sklearn.datasets.fetch_kddcup99(subset='SA', percent10=True)`
- Same train/test/scaling protocol

DMKDE hyperparameters: `feature_dim=1024`, `sigma=5.0`

| Detector | ROC-AUC | PR-AUC | fit (0.1.0) | inference (0.1.0) |
|---|---:|---:|---:|---:|
| **DMKDE** | **0.9965** | **0.9807** | 4.3s | 22.4s |
| Mahalanobis | 0.9960 | 0.9791 | 0.01s | 0.03s |
| OneClassSVM | 0.9951 | 0.9799 | 0.53s | 0.48s |
| LOF | 0.9805 | 0.8627 | 0.40s | 0.52s |
| Isolation Forest | 0.9584 | 0.8828 | 0.34s | 0.14s |

On this seed-42 split DMKDE has the highest ROC-AUC and PR-AUC, but by
0.0005 ROC-AUC over Mahalanobis and 0.0008 PR-AUC over OneClassSVM, which
is well inside the seed-to-seed variation:

**Seed variation** (same command with `--seed 1` / `--seed 2`, run by an
independent reviewer on the 0.1.1 release candidate, whose DMKDE scores are
bit-identical to 0.1.0 and 0.1.1):

| Detector | ROC-AUC seed 1 | PR-AUC seed 1 | ROC-AUC seed 2 | PR-AUC seed 2 |
|---|---:|---:|---:|---:|
| OneClassSVM | **0.9971** | **0.9868** | **0.9986** | **0.9935** |
| DMKDE | 0.9962 | 0.9842 | 0.9957 | 0.9741 |
| Mahalanobis | 0.9952 | 0.9747 | 0.9971 | 0.9819 |
| LOF | 0.9797 | 0.8617 | 0.9826 | 0.9109 |
| Isolation Forest | 0.9691 | 0.9097 | 0.9712 | 0.9154 |

On seeds 1 and 2 OneClassSVM is best on both metrics, and on seed 2 DMKDE
is third by ROC-AUC. The fair summary is that DMKDE, Mahalanobis and
OneClassSVM are statistically indistinguishable at the top of this
dataset.

## Synthetic scenarios (`benchmark.py`)

Four controlled scenarios, all 4-D, 400 training + 300+300 test
(`python python/benchmark.py`, seed 42, `feature_dim=256`, `sigma=1.5`;
re-run with 0.1.1 and 0.2.0, identical to 0.1.0 to the printed digits):

| Scenario | DMKDE | Mahalanobis | IsolationForest | OneClassSVM | LOF |
|---|---:|---:|---:|---:|---:|
| Gaussian normal | 1.0000 | 1.0000 | 0.9989 | 1.0000 | 1.0000 |
| Bimodal manifold | 1.0000 | 0.4361 | 1.0000 | 1.0000 | 1.0000 |
| Ring (hub anomalies) | 0.9617 | 0.0000 | 0.0000 | 0.0000 | **0.9884** |
| `sklearn` (`make_classification`, 300+107 test) | 0.9315 | 0.9174 | 0.9190 | 0.9317 | **0.9447** |

The fourth scenario, `sklearn`, is part of `benchmark.py` but was left out
of earlier versions of this table; LOF wins it.

**Seed variation** (`python python/benchmark.py --seed S --scenarios ring
sklearn`, S = 0-9, run with 0.1.1; re-run with 0.2.0, identical):

| Seed | ring DMKDE | ring LOF | sklearn DMKDE | sklearn best (AUC) |
|---:|---:|---:|---:|---|
| 0 | 0.8947 | **0.9919** | 0.9050 | LOF (0.9051) |
| 1 | 0.9842 | **0.9944** | 0.8396 | LOF (0.8677) |
| 2 | 0.8318 | **0.9907** | 0.8458 | Mahalanobis (0.9090) |
| 3 | 0.9667 | **0.9846** | 0.8706 | OneClassSVM (0.9284) |
| 4 | 0.9363 | **0.9869** | 0.7994 | LOF (0.8213) |
| 5 | 0.9364 | **0.9877** | 0.7942 | LOF (0.8457) |
| 6 | 0.9718 | **0.9879** | 0.9027 | LOF (0.9209) |
| 7 | 0.8874 | **0.9901** | 0.8309 | LOF (0.8824) |
| 8 | 0.8937 | **0.9847** | 0.8452 | OneClassSVM (0.8602) |
| 9 | 0.9443 | **0.9856** | 0.7550 | LOF (0.8263) |

On the ring, LOF beats DMKDE on every seed 0-9 (DMKDE ranges 0.83-0.98,
so the seed-42 value 0.9617 is not representative); Mahalanobis, Isolation
Forest and OneClassSVM stay at ~0.000 on every seed. On `sklearn`, DMKDE is
never the best: LOF wins 7 of these 10 seeds (an independent reviewer's run
counted 8/10; seed 0 is a 0.0001 tie between LOF and DMKDE).

The **ring scenario** is the diagnostic: normal data lives on a
hypersphere of radius 3, anomalies cluster at the centre. Mahalanobis,
Isolation Forest, and OneClassSVM all score **exactly 0.000 AUC** because
the empirical mean (and the tree's split heuristics) place the "most
normal" prediction at the centre — i.e. exactly where the anomalies live.

**Only DMKDE and LOF survive, and LOF is higher.** This is the regime where the
density-matrix interpretation pays off: anomaly score is the Born-rule
probability of measuring `x` in the training subspace, which correctly
returns near-zero for points that are nominally close to the mean but
far from the manifold the training data lives on.

## When does DMKDE win?

| Data property | DMKDE rank | Why |
|---|---|---|
| Single-Gaussian normal | tied / slightly behind | Mahalanobis is mathematically optimal |
| PCA-pretreated features | behind Mahalanobis | Same reason — post-PCA the data is approx. Gaussian |
| Multi-modal manifold | ties with IsolationForest / OCSVM / LOF; beats Mahalanobis | Density-matrix scoring captures higher-order structure |
| Non-convex "normal" support | second to LOF (every seed 0-9) | Ring/hub scenarios where mean-based methods invert |
| `make_classification` one-class | behind LOF (best on 0 of 10 seeds) | |
| Numeric network-flow features (KDDCup, categoricals dropped) | tied with Mahalanobis / OneClassSVM | Best on seed 42, OneClassSVM best on seeds 1-2 |

The C++ demo (`make bench`, `examples/benchmark.cpp`) draws its scenarios
with its own generator (`std::mt19937_64` and, since 0.2.0, the library's
portable normal sampler, so the data is the same on every OS), so its
numbers differ from the Python harness above (0.2.0 on Linux x86_64: for
example ring 0.8337, bimodal Mahalanobis 0.4503, and a 200-update streaming
demo; 0.1.x drew platform-dependent data and gave ring 0.8358, bimodal
Mahalanobis 0.4389 on Linux). The tables in this file and in the README
come from the Python scripts.

## Unique capabilities

In addition to the AUC numbers above, DMKDE has features none of the
baselines provide:

- **Streaming rank-1 EMA updates** (O(D²) time, O(1) extra memory per sample) — verified to maintain
  `AUC = 1.000` after 300 sequential updates on the bimodal manifold
  scenario (see `example.py`).
- **Born-rule interpretation** — the score is the expectation value
  `⟨φ(x)|ρ|φ(x)⟩` of the density operator ρ in the state |φ(x)⟩. The optional
  Qiskit backend reproduces it by classical **statevector simulation only**
  (`Statevector.expectation_value`); there is no hardware path, and loading
  an arbitrary |φ(x)⟩ needs a generic state-preparation circuit, not a
  compact parameterised one.
- **Closed-form fit** — no iterative optimisation; the only
  hyperparameters are `feature_dim` and `sigma`. But results are
  **sensitive to σ**: σ must grow with the number of (standardized)
  features, and at the default σ = 1 with 20 or more features every score
  sits at the random-feature noise floor (~1/D) and the AUC is ≈ 0.5. The
  σ values above were tuned by hand on the reported split.

## Reproducing

```sh
pip install -e .          # builds the C++ extension
pip install scikit-learn pandas

python python/benchmark.py             # synthetic scenarios
python python/benchmark_creditcard.py  # Kaggle credit-card-fraud
python python/benchmark_kdd.py         # KDDCup'99 SA subset
```

All scripts accept `--seed`, `--feature_dim`, `--sigma` etc. The defaults
of `benchmark.py` and `benchmark_kdd.py` match the numbers above;
`benchmark_creditcard.py` needs `--feature_dim 1024 --sigma 7.0`.
